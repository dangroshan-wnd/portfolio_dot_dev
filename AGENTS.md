# Working on dangroshan.dev

Dan Groshan's personal site, live at https://dangroshan.dev. It is for Dan himself first and future employers and recruiters second. The site is playful and illustrated, starring Dan's dogs **Noodles** and **Shady**.

Read before changing anything visual:

- [docs/style-guide.md](docs/style-guide.md): colors, type, the paper-cutout illustration style, motion, and layout rules
- [docs/characters.md](docs/characters.md): the Noodles and Shady character sheet

Skills for repeatable jobs (same instructions for Claude Code and Codex):

- `draw-noodles-and-shady`: put the dogs into a scene or a small cameo, on-model
- `add-game`: add a game under `games/`

## Hard rules

1. **Dan writes every word.** Never draft or rewrite copy: bios, job history, project write-ups, movie notes, game blurbs. Lay out the content Dan gives you. Where text is missing, leave an obvious placeholder such as `[Dan: intro paragraph]` and tell him. Short functional UI labels inside a game (Score, Play again) are fine.
2. **Don't invent facts about Dan.** That covers employers, dates, titles, metrics and project details. Ask him.
3. **Dark only.** There is no light mode. Use the tokens in `style.css`.
4. **The repo is public and every push to `main` deploys.** Never commit secrets, private notes, or anything Dan hasn't approved for the public site.
5. **The goose and the pig are retired.** Only Noodles and Shady appear.

## How the site works

- Plain static HTML, CSS and JS with no framework and no build step. GitHub Pages serves the `main` branch of `dangroshan-wnd/portfolio_dot_dev`. The `CNAME` file holds the domain. DNS is at Porkbun.
- Pages are folders, so their addresses are `/work/`, `/projects/`, `/movies/` and `/games/`. The sidebar order is Home, Work, Projects, Movies, Games.
- **Home, Work, Projects and Movies are "See you soon..." placeholders** generated by `tools/build_placeholders.py`. Edit that script and rerun it (`python3 tools/build_placeholders.py`) rather than hand-editing the generated HTML. When a page gets real content, it stops being generated: remove its entry from `SPECS` in the script.
- **Games is a real, hand-written page** (`games/index.html`). It embeds the selected game in an iframe, with one tab per game. Its `GAMES` list drives the tabs, and `#<slug>` in the URL selects a game. Each game also works standalone at `games/<slug>/`. When embedded, a game hides its own header (it detects `window.self !== window.top`). The page loads each game with a `?v=<timestamp>` cache-buster, so game updates show up immediately inside the embed.
- **Parked:** a shared high-score leaderboard for the games. The proposed approach is a Cloudflare Worker with D1, three-letter initials, server-issued run tickets and seeded rounds. Don't build it until Dan picks it back up.
- `style.css` holds the shared theme, sidebar, and animation classes. `site.js` fits each page's scene to its panel.
- `assets/characters/*.svg` are reference drawings of the dogs, generated from the same script.

## Preview and verify

```sh
python3 -m http.server 8765          # then open http://localhost:8765/
```

Folder links like `work/` don't work when you open the files directly, so always preview through a server.

Before you push, check every page you touched at desktop and phone widths. A headless Chrome screenshot is enough:

```sh
C="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$C" --headless=new --hide-scrollbars --window-size=1440,900  --screenshot=desk.png  http://localhost:8765/work/
"$C" --headless=new --hide-scrollbars --window-size=600,1100 --screenshot=phone.png http://localhost:8765/work/
```

Headless Chrome won't render narrower than about 500px, so use 600×1100 for "phone". After pushing, wait about a minute and confirm the live page returns 200 and shows the change.
